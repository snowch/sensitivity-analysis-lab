Lesson 4 of 4

Work from logs

Use synthetic pipeline records to see which inputs help predict job delays.

Test on jobs the model hasn’t seen

On the first run, the page generates 10,000 synthetic pipeline records. It trains a random forest on 8,000 rows and tests it on the other 2,000. New shuffles during this visit reuse the fitted forest and test rows.

A forest averages predictions from decision trees, which split data into groups. The mean absolute error (MAE) averages the size of each prediction error in milliseconds. An error of 5 ms counts the same whether the prediction is too high or too low.

Shuffle one signal and measure the error again

Permutation importance shuffles the values in a test column and predicts again with the same model. Compare MAE before and after the shuffle to measure how much accuracy the predictor loses.

Do the cache counters carry the same signal?

Shuffle the test data

Leave Shuffle at Individual features and select Run permutation importance. The page repeats each shuffle five times at the starting settings.

Shuffle

Shuffle repetitions and CSV download

Test error and feature importance

Compare Forest test MAE and Median-only test MAE. The median baseline always predicts the middle latency from the training data. Which has the smaller average error on the held-out jobs?

Shuffle both cache counters

Set Shuffle to Group the cache counters and leave Shuffles per feature or group at 5. Select Run permutation importance again. In Cache counter comparison, compare Increase in MAE (ms) for Edge miss rate, Origin fetch rate and the pair. Does shuffling the pair hurt accuracy the most?

Read the result

An edge cache stores copies close to users. Edge miss rate is the share of requests with no usable copy there. Origin fetch rate is the share that had to reach the original source.

The synthetic data make both noisy measures of the same cache behaviour. Shuffling one leaves the other available. Moving both together keeps them aligned with each other while breaking their link to the original jobs.

Use the increase in test MAE after a shuffle to see which signals the predictor relies on for accurate latency estimates. If you need to decide whether to add worker capacity, compare current and higher capacity on the same workload. Before the test, specify how much latency must fall and the maximum extra cost per job.

Check your reasoning

Shuffling the cache pair raises test MAE much more than shuffling either counter alone. What does this tell you about the fitted model?

How the synthetic data and predictor are prepared

The data include noisy latency measurements, blanks in the two cache counters and an irrelevant deployment-age column. The page fills blank values with medians calculated from the training rows. The forest averages predictions from 24 trees fitted on resampled training rows.

The output reports the mean change in error and how much that change varies across shuffles on the same test set. See the data generator and evaluation code.
