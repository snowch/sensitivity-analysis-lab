Plan a fair test on real logs

Choose test data, a baseline and a shuffle that answer the question you actually have.

Test the predictor on realistic unseen examples

Suppose you want to predict next week’s delivery times. Fit the model on earlier weeks and reserve later deliveries for testing. If the question is how well the model works for new drivers, put all records for any one driver in the same set. Use some drivers for training and different drivers for testing. Fit any rules for filling missing values on training rows only.

Compare the model’s error with a simple baseline, such as always predicting the training median. If late deliveries matter most, check errors on those cases as well as the mean absolute error (MAE) across all test deliveries. MAE averages how far each prediction is from the measured time.

Shuffle the signal you want to investigate

Distance and delivery zone can carry overlapping information. Shuffle them separately to see how much the fitted model relies on each. Shuffle them as a pair to see how much the model relies on their shared information. Use the same row order for both columns so their values stay aligned.

Even a paired shuffle can put a distance and zone beside an implausible route. Check whether the invented combinations make sense. Repeat the shuffle to see whether the conclusion depends on the particular row order.

Choose the meaning of importance

Permutation importance measures the change in test error when a fitted predictor loses alignment with a signal. The value depends on the fitted model, data, loss and shuffle rule. Sobol indices decompose output variance under an input distribution, usually with independent inputs. Shapley effects allocate global variance under a specified joint distribution.

A predictive Shapley explanation can allocate the difference between one prediction and a reference prediction, such as the average across all deliveries. Take a 20-minute reference. In an illustrative calculation, using distance alone gives 26 minutes, using zone alone gives 24 minutes, and using both gives 32 minutes. Distance adds 6 first or 8 after zone, so its credit is (6 + 8) ÷ 2 = 7 minutes. Zone gets (4 + 6) ÷ 2 = 5 minutes. The credits add to the 12-minute difference. A different reference population or rule for filling unknown features can change those credits. To estimate what changing the route would do, run a controlled comparison or use a defensible causal design.

Write a test plan before departure

Suppose your predictor can use distance, delivery zone, and the recorded arrival timestamp. You want a prediction before the van leaves. On paper, list which inputs are available before departure. Pick two to shuffle together. Then write a simple test to see whether changing the route reduces delays.

Example test plan

Exclude the recorded arrival timestamp because it becomes available after the prediction. Compare individual and paired shuffles of distance and zone on later deliveries. To test a route change, compare comparable deliveries with the current and alternative routes and measure late arrivals and driver time.
