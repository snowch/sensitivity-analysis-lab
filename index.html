Start here

Why learn sensitivity analysis?

The pipeline usually finishes a job in about 100 ms. When it slows down, the dashboard offers a dozen plausible explanations. Tuning the wrong input can cost a day and leave the slow jobs untouched.

Sensitivity analysis asks how much an output changes as inputs vary in a model. With recorded runs, feature attribution asks which signals a fitted predictor uses. You’ll use both kinds of evidence to choose a change worth testing.

Before you start

You’ll compare numbers in simple tables and read horizontal bars. You can complete every exercise in your browser without writing code or having taken a statistics course.

Quick refresher on the measurements
Latency
Time for a job to finish. A second is 1,000 milliseconds (ms).
Median and p95
Half of runs finish by the median time. About 95 in 100 finish by the p95 time, so p95 is a way to track slow jobs.
Cache hit rate
The percentage of requests served from the cache. Moving from 70% to 80% is a rise of 10 percentage points.

Rank the knobs

How can you make a first shortlist when 13 inputs could matter?

Draw possible runs and compare their ranks

Start with a formula for end-to-end latency and a plausible range for each input. A Monte Carlo simulation repeatedly draws values from those ranges, runs the formula, and records the result. Here every value within a range is equally likely, and each input is sampled independently.

Spearman rank correlation orders the runs twice, once by the input and once by latency. Similar order gives a score near +1, reverse order gives a score near −1, and little consistent ordering gives a score near zero. Look at the magnitude to shortlist inputs and the sign to read the direction.

Try it on all 13 inputs

  1. Predict which way latency moves as payload size increases.
  2. Run the defaults. Name the two largest bars and read their signs.
  3. Change the seed under simulation settings and rerun. Did your shortlist change?

With the supplied ranges, cache hit rate and payload size dominate. Higher hit rates reduce time spent on cache misses, while bigger payloads cost more to process. Spearman’s ρ describes monotonic association. Adding the scores cannot tell you how much variance the two inputs explain.

Lesson 2 of 3 · 7 min

Break the ranking

Can your shortlist survive a wider network range or a queue that saturates?

Ask two questions about variation

For the baseline, network round-trip time (RTT) ranges across 4 ms. The wide scenario spans 63 ms. In both, every extra millisecond of RTT adds one millisecond of latency. A wider RTT range gives that same input more room to move the result. Your ranking depends on which conditions you put in the model.

Variance measures how far latencies spread around their average, giving more weight to large deviations. First-order Sobol estimates the fraction of latency variance explained by one input on its own. Total-order Sobol also includes every interaction involving that input. Read 0.70 as about 70% of modelled variance, given the sampled ranges. A large gap between the bars suggests the input matters through interactions.

Change one assumption at a time

  1. Run Baseline and note the top driver.
  2. Predict where RTT will rank, then run Wide network. Only the RTT range changes.
  3. Run Queue saturation, which restores the baseline RTT range. Compare the two Sobol bars for arrival rate and worker capacity, then check where each ranks by Spearman.

Understand the queue rule and Sobol estimates

The queue adds 155 ms when arrival rate reaches 750 jobs/s and worker capacity is at most 800 jobs/s. Each condition covers one quarter of its input range. With independent inputs, the two hold together in about one run in sixteen. The abrupt penalty is an illustrative stand-in for a saturation regime.

To estimate the indices, the simulation draws two independent sample matrices. It then exchanges one input column at a time and reruns the formula. Squared changes in the output help estimate total-order sensitivity. Two inputs can share an interaction, so totals can sum to more than one. Small negative first-order values can occur from sampling noise.

Read the scenario results

Widening network RTT increases its contribution while its coefficient in the latency formula stays at 1. Measure the actual RTT range before investing in network work.

Under saturation, arrival rate and capacity dominate the Sobol total-order chart, even with modest rank correlations. Their first-order estimates are much smaller because the large delay depends on both. Cache hit rate still matters for typical runs. Investigate the queue when the latency tail is the problem.

Work from logs

When the formula is unavailable, what can a predictor tell you about your logs?

Break the link between a signal and its row

First fit a model on 8,000 runs, then measure how far its predictions miss on 2,000 unseen runs. Mean absolute error (MAE) is the average size of those misses, in milliseconds.

Permutation importance shuffles the values in one test column, leaving the measured latencies and other columns in place. The model stays fixed. If its error rises, that column carried information the model used. A second column carrying similar information can cover for it, so try shuffling the two together.

Test two ways of shuffling

  1. Run Individual features. Check the forest beats the median-only predictor on held-out rows, then find both cache counters.
  2. Predict what happens if the model loses both signals at once. Select Group the cache counters and rerun.
  3. Compare the three error increases in Compare the cache shuffles. What information did the two counters share?

Inspect the dataset and evaluation

These synthetic logs include measurement noise, blanks in two columns and an irrelevant deploy-age column. Edge miss rate and origin fetch rate are noisy proxies for the same unlogged cache behaviour. Twelve other columns describe pipeline settings or operating conditions.

The browser shuffles rows once for a fixed 8,000/2,000 train/test split. It imputes missing entries with training medians, fits 24 bootstrap regression trees on the training rows, then measures error on the same held-out rows before and after each shuffle. The shuffle standard deviation quantifies variation across shuffle draws on this split. See the data generator, forest and permutation code.

Read the attribution result

Compare both shuffle modes. When you shuffle just one cache counter, its partner can still carry similar information. Shuffling them together preserves their relationship with each other and disrupts their joint relationship with latency.

Importance describes the model’s reliance on its inputs. To test an intervention, replay the same burst workload and compare current worker capacity with increased capacity. Randomise the order across repeated runs, hold payload and cache policy steady, and compare p95 latency alongside resource cost.
